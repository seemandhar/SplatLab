How SplatLab works

SplatLab is a thin control panel over the existing autonomous lab. There is no separate engine: the intelligence is Claude Code running the /research master prompt inside a persistent tmux session. All durable state lives on disk in workspace/run_<ts>/ledger.json and events.jsonl. This dashboard reads that state and drives the same lifecycle commands — so closing your laptop, refreshing the page, or restarting the server all reconnect to the same live job.

Every control, and what it actually does

ControlEquivalent commandWhat happens under the hood
Launch Run/research "idea" --hours NWrites your idea + flags into config.yaml, starts claude --dangerously-skip-permissions in the splatlab tmux session, and sends the /research command. The master runs init_workspace.sh, seeds a ledger, and loops for N hours dispatching ~30 subagents.
Stop/research-stopAtomically sets status: stopping in the ledger. The master notices at its next iteration (≤5 min), lets in-flight scenes finish, and halts. Nothing is hard-killed.
Resume/research-resumeStarts a session and sends /research-resume. The master heals stalled experiments and continues the most recent run from its ledger checkpoint.
Killtmux kill-sessionHard-stops the tmux session immediately. The ledger survives intact — use Resume to pick the run back up. Use this only if the master is wedged.
Overview/research-statusReads the ledger and shows status, thesis, ideas, the current best result, milestone progress, and budget.
Experiments—The experiments[] array from the ledger, plus the smoke → probe → multi-scene cascade each idea passes through.
Livetail -f events.jsonl / tmux attachStreams new ledger events over SSE and tails the master's tmux console (read-only).
Paper—Serves the compiled paper.pdf, the generated figures, and reports (RUN_REPORT, thesis, bottleneck/limitation analyses).
Runs—Lists every run on disk so you can inspect or resume any of them.

The cascade (how ideas earn compute)

Each idea is filtered cheaply before it gets a GPU: a 500-iteration smoke test (~3 min) gates a single-scene full-iteration probe, which gates the expensive multi-scene deployment. Most ideas die at smoke or probe — that is the point. Only signal that survives full-iteration single-scene training earns the 7× multi-scene fan-out.

Session persistence

The dashboard keeps no run state of its own. On load it asks the backend for the live run and reconnects. Because the run lives in tmux and on disk — independent of both the browser and this server — you can refresh, close the laptop, or restart the backend and pick up exactly where you were.

Remote access & auth

By default the server binds 127.0.0.1 (localhost only). To reach it from a laptop, run it with HOST=0.0.0.0 GSS_TOKEN=<secret> and open http://<box>:8420; the page will ask for the token once and remember it. Never bind 0.0.0.0 without a token.
